# 本地环境搭建

本文说明从零把问渠跑起来需要准备什么。所有配置项都通过环境变量或本地中间件配置提供，仓库内不保存任何真实凭据。

## 1. 软件依赖

| 组件 | 建议版本 | 说明 |
| --- | --- | --- |
| JDK | 21 | 后端编译与运行 |
| Maven | 3.9+ | 构建 |
| Node.js | 20+ | 前端构建 |
| MySQL | 8.0 | 业务数据 |
| Redis | 7.x | 缓存、计数、令牌白名单 |
| Elasticsearch | 9.x | 检索与向量索引 |
| Kafka | 4.x（KRaft） | 计数聚合、事件同步 |
| Canal | 1.1.8 | 订阅 binlog 投递事件 |

> Elasticsearch 版本需与后端依赖的客户端对齐（`elasticsearch-java` 9.2.x），跨大版本会在建索引时直接失败。

Redis 使用独立库 `db 1`（`spring.data.redis.database: 1`），避免与同一实例上的其它项目共用 `db 0`。
Redisson 复用同一个 `RedisProperties`，缓存与分布式锁会自动落在同一个库，不需要单独配置。

> 清理缓存时按前缀删除（`KEYS feed:*` → `DEL`），不要执行 `FLUSHALL` / `FLUSHDB`，否则会连带清空同实例上其它项目的数据。

## 2. 数据库

```sql
CREATE DATABASE wenqu DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

```bash
mysql -uroot -p < wenqu_backend/db/schema.sql
```

建表结果为 6 张：`users`、`login_logs`、`know_posts`、`following`、`follower`、`outbox`。

> 用户标识列名为 `zh_id`，与后端实体字段 `zhId` 对应。若复用旧库，需要先按 `schema.sql` 调整列名。

## 3. 环境变量

后端通过 `${VAR:默认值}` 读取，未设置的项回落到 `application.yml` 中的本地默认值。

| 变量 | 用途 | 是否必须 |
| --- | --- | --- |
| `MYSQL_USERNAME` / `MYSQL_PASSWORD` | 数据库账号 | 否，默认 `root` / `123456` |
| `DEEPSEEK_API_KEY` | 摘要生成（缺失会导致应用启动失败） | **是** |
| `DASHSCOPE_API_KEY` | 向量模型（缺失会影响 RAG 与索引） | **是** |
| `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` | 对象存储直传 | 上传功能需要 |
| `OSS_BUCKET` | 对象存储桶名 | 上传功能需要 |
| `OSS_ENDPOINT` / `OSS_PUBLIC_DOMAIN` | 对象存储端点与公网域名 | 否 |
| `CANAL_USERNAME` / `CANAL_PASSWORD` | Canal 账号，需与 Canal 实例配置一致 | 否，默认 `canal` / `canal` |

写入方式（Windows，写入用户级变量，重开终端生效）：

```powershell
setx DEEPSEEK_API_KEY "你的 key"
setx DASHSCOPE_API_KEY "你的 key"
```

bash / zsh：

```bash
export DEEPSEEK_API_KEY="你的 key"
export DASHSCOPE_API_KEY="你的 key"
```

> 注意：环境变量在进程启动时读取。已经打开的终端、IDE 需要重启才能读到新值。

## 4. Elasticsearch

单节点开发配置（`config/elasticsearch.yml`）：

```yaml
cluster.name: my-es-cluster
node.name: node-1
network.host: 0.0.0.0
http.port: 9200
discovery.type: single-node
xpack.security.enabled: false
xpack.security.enrollment.enabled: false
xpack.security.http.ssl.enabled: false
xpack.security.transport.ssl.enabled: false
```

索引 `wenqu-ai-index` 由 `spring.ai.vectorstore.elasticsearch.initialize-schema=true` 在启动时自动创建，维度 1536，需与向量模型输出维度一致。

## 5. Kafka（KRaft）

不依赖 ZooKeeper，单个 broker 同时承担 controller 角色。`config/server.properties` 关键项：

```properties
process.roles=broker,controller
node.id=1
controller.quorum.bootstrap.servers=localhost:9093
listeners=PLAINTEXT://:9092,CONTROLLER://:9093
log.dirs=<数据目录>
```

首次启动前需要格式化存储目录：

```bash
kafka-storage.bat random-uuid
kafka-storage.bat format -t <上一步的 UUID> -c config/server.properties
```

使用到的主题：`counter-events`（计数事件）、`canal-outbox`（关系变更事件）。broker 开启自动建主题即可，否则需手动创建。

**Windows 11 注意**：`kafka-server-start.bat` 内部调用 `wmic`，该系统已移除该命令，脚本会报 `'wmic' is not recognized`。直接用 java 启动：

```powershell
java -Xmx1G -Xms1G -cp "<kafka 目录>\libs\*" kafka.Kafka "<kafka 目录>\config\server.properties"
```

## 6. Canal

### 6.1 MySQL 侧要求

```sql
-- 确认 binlog 配置
SHOW VARIABLES WHERE Variable_name IN ('log_bin','binlog_format','binlog_row_image','server_id');
-- 期望：ON / ROW / FULL / 非 0

-- 同步账号
CREATE USER 'canal'@'%' IDENTIFIED BY '你的密码';
GRANT SELECT, REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'canal'@'%';
FLUSH PRIVILEGES;
```

### 6.2 实例配置

`conf/<instance>/instance.properties` 需要与后端配置对齐：

```properties
canal.instance.master.address=127.0.0.1:3306
canal.instance.dbUsername=canal
canal.instance.dbPassword=与 CANAL_PASSWORD 环境变量一致
canal.instance.filter.regex=wenqu\\.outbox
```

`filter.regex` 的格式是 `库名\.表名`，库名必须与实际库一致，否则收不到任何事件。该表 `outbox` 是关系变更事件的发件箱。

### 6.3 位点重置

Canal 会把解析位点缓存在 `conf/<instance>/meta.dat` 与 `h2.mv.db`。如果 MySQL 的 binlog 已经轮转清理，启动会报：

```
errno = 1236, Could not find first log file name in binary log index file
```

处理方式：停止 Canal → 备份并删除上述两个文件 → 重启，让它重新定位到当前 binlog 位点。

## 7. 启动顺序

1. MySQL、Redis
2. Elasticsearch（等 9200 可访问）
3. Kafka（等 9092 可访问）
4. Canal（等 11111 可访问）
5. 后端：`cd wenqu_backend && mvn spring-boot:run`
6. 前端：`cd wenqu_frontend && npm install && npm run dev`

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `DeepSeek API key must be set` | `DEEPSEEK_API_KEY` 未生效 | 检查变量是否写入，重开终端后再启动 |
| 调用 AI 接口返回 401 | key 无效或为空 | 用 `curl` 直接请求模型接口验证 key |
| 建索引报版本不兼容 | ES 服务端与 `elasticsearch-java` 跨大版本 | 服务端升到与客户端同大版本 |
| Canal 报 `errno = 1236` | 位点缓存指向已清理的 binlog | 删除 `meta.dat` / `h2.mv.db` 后重启 |
| Kafka 启动报 `AccessDeniedException ... .checkpoint.deleted` | 上次被强制结束，残留只读标记文件 | 删除 `log.dirs` 下 `__cluster_metadata-0` 中的 `*.checkpoint.deleted` |
| Kafka 报 `'wmic' is not recognized` | Win11 移除了 wmic | 用 `java -cp libs/* kafka.Kafka` 直接启动 |
| 关注/点赞后计数不更新 | Kafka 或 Canal 未启动 | 按第 7 节顺序启动后重试 |
